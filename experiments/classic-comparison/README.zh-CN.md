### 公共环境与模型

- RoboDojo 冻结提交：`726e9aabfaa642203722eb126f5eaf0f37f3e1ad`；环境 `arx_x5`、双臂 `dual_x5`、单环境、eval_seed=0，重放已保存布局。每项保留自己的原生步数上限。
- 仿真物理 dt=0.004 秒、控制/相机采集 25 Hz；已测两个任务的上限都是 200 个控制步。200 步约 8 秒仿真推进，不等于 8 秒现实任务时间。
- 已运行日志记录 NVIDIA RTX 3090，约 24 GB 显存。π0.5 与仿真共享 GPU；初始化、推理、任务与退出时间分别记录。
- 所有已测语言模型条件请求 `gpt-6-astra`、Responses、`xhigh`，经同一第三方服务和本机计数代理；单请求超时 180 秒，图像最长边 480，不允许模型回退。π0.5-only 不调用语言模型。
- VLA 权重：`RoboDojo-sim-arx_x5-joint-0/59999`；OpenPI/JAX 配置 `pi05_base_aloha_full_sim_arx-x5_seed_0`。原 π0.5-only 每次预测 50×14，执行前 15 个关节目标；Hybrid 另有 Astra 审查与接管。
- Direct/早期 Hybrid 输入为三相机 RGB、关节/手部实测状态、任务指令和机器人 FK；RPent、GaP、PhyAgentOS 本机条件提供公共 RGB-D/标定接口，实际消费路径见逐次记录；模块化条件按配置消费 RGB 或 RGB-D。不把可用深度等同于每个组件都使用深度。

## 怎样开始跑选定任务

先比较通用的 `astra_direct`、`pi05_only`、`astra_hybrid`，验证每配置可启动，再扩展框架。铲子专用 ReAct skill、定制 Phy skill、`modular_pickup`、固定 `target_text=shovel` 的新Hybrid感知配置需先泛化任务接口。入口能接受任务名不表示控制器已支持全部任务。

下面是单个开发布局的命令示例，未在本次执行；沿用1200秒预算方便与历史主试跑对应。正式比较须固定预算、感知许可与适配版本；若改420秒，应把所有基线一起重跑。

```bash
cd /path/to/robot-agent-eval
/path/to/robodojo-env/bin/python -m robot_agent_eval.runner \
  --method astra_hybrid \
  --manifest manifests/classic-development.json \
  --task general_pickup --layout 50 --limit 1 \
  --config configs/model.pilot.json
```

每配置10个测试布局使用 `classic-test-screening.json --task <配置名> --limit 10`；runner默认只跑1例。清单按上表的配置顺序分组，首轮测试用 `--limit 60` 会跑前6个配置各10例；逐任务运行更方便检查进度。测试布局冻结后不再用于修改提示词或skill。成功由原生判定，预算停止的原生分数保留未知；报告按任务、标准/随机条件分开，再给等任务权重平均与重复区间。
