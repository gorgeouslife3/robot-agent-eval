# 闭环 Skill、事件触发与几何契约：审查及实施路径

日期：2026-10-16。范围：审查公开研究和本机已有结果，提出实现与验证方案。本次未启动新机器人实验、付费模型请求或实机动作。下文“建议”“新增”均不是已取得的效果。

## 1. 审查结论与证据边界

建议成立，但需要合成一个完整机制：**大模型委托有边界的子任务；Skill 在边界内持续观察、控制和恢复；状态管理器保存带来源的事实；事件调度器只将超出能力或授权的问题交给大模型。** 几何契约是这些机制共同依赖的基础。

| 建议 | 判断 | 必须补充的条件 |
|---|---|---|
| Skill 内部观察与纠错 | 优先实施，已有本地执行雏形 | 可执行状态机、前置条件、阶段后置条件、恢复上限、取消和超时；仅写 SKILL.md 不会产生控制能力 |
| 事件触发大模型 | 方向合理，收益尚待配对验证 | 可靠事件判据、未知状态、有界盲区、关键动作执行门、去抖与超时；监控成本也要计入 |
| 结构化任务状态 | 应实施，但不能预设完全替代历史 | 区分命令/观测/假设；保留来源、关键图像与失败动作；支持失效和回退 |
| 相机与夹爪几何 | 最先统一 | 统一坐标和单位、动态手眼变换、控制 frame 与抓取 frame、实际到达验证 |

### Astranomy 直接支持什么

来源：[NVIDIA Astranomy，2026-10-14](https://research.nvidia.com/labs/srl/projects/astranomy/)，本次读取日期 2026-10-16。

- 主评测为 RoboLab-120，DROID/Franka + Robotiq，15 Hz；推理时暂停仿真。并非本机双臂 ARX X5/RoboDojo，也未验证真实世界持续变化时的闭环。
- 30 任务几何消融中，Direct 的基础提示、加夹爪、加相机、两者都加的成功率分别为 19.3%、35.3%、62.7%、72.7%；Agentic 基础与完整几何为 83.3%、86.0%。支持明确几何，不能把 53.4 个百分点直接当作本机收益。
- Direct 仅当前观测为 49.3%，三帧历史为 72.7%。Agentic 的 23 任务上下文子集：完整历史 23/23，完整文本加近期图像 22/23，近期文本加近期图像 17/23，只有视觉历史 13/23。支持保留动作和进度信息；**没有证明结构化摘要与完整历史等效**。23/23 也不是泛化成功率 100%。
- Direct 动作段从 3–15 延长到 16–32，调用减少约 62%，成功率从 72.7% 降至 66.7%。图中约 25 秒的完成时间是任务执行时间，不能直接解释成含推理的墙钟时间。扩大委托范围必须同时保留本地反馈。
- 成功回合的估算总时长中，推理占 Direct 97.0%、Agentic 97.8%、Orchestrated 94.9%。这是减少阻塞调用的动机，不是事件策略已经有效的证据。
- Orchestrated 接管约占仿真步数的 14.5%；接管块中的抓取问题和错误目标/计划分别占 64.4%、20.2%，分类由 VLM 辅助完成。不能据此推导“其余 85.5% 审查可以删除”，因为无需接管的审查也可能发挥确认作用。
- 显式规划、运动误差文字回执在其消融中未显示明显额外收益。因此应把状态和误差真正接入执行门、恢复与调度，而非只增加提示词。

### 本机有哪些直接证据

1. [首轮报告](../report.zh-CN.md)：同一铲子案例，Direct 原生成功约 775.84 秒，Hybrid 约 424.22 秒；Direct 只有 2.84 秒仿真推进。说明模型循环存在较大等待，单案例不能估计总体加速。
2. [感知/操作消融](../results/perception-manipulation-ablation/report.zh-CN.md)：语义选择回放条件下，本地几何抓取约 88 秒成功；人为提高首次抓取点 35 mm 的空抓实验，本地恢复产生 `[False, True]` 试抬结果，最终原生成功，约 111.46 秒。证明本地执行/恢复链路可运行；初始化复用过历史模型选择，不能声称完整任务从零无需大模型。
3. 同一报告记录恢复后 mask 中位高度 0.884 m、TCP 0.810 m，原因未区分。姿态变化或身份漂移都有可能；最终原生成功不证明验证器可靠。
4. [Hybrid 感知报告](../results/astra-hybrid-perception/report.zh-CN.md)：新增几何主要用于确认目标侧，尚无证据证明它改变了精确抓取。数据进入模型输入不等于有效利用。
5. [后端比较](../results/classic-hybrid-backends-20261013/report.zh-CN.md)：已结束 40/690 次后停止。抓取候选组未显示普遍改善；候选不包含运输、放置、插入与协调的完整轨迹。优先补齐执行流程比继续堆候选模型更有依据。
6. [监督效率第二部分报告](../experiments/supervision-efficiency/results/part2/report.zh-CN.md)当前文件仍为 queued、0/15。虽然已有实现，不能报告事件触发的实测收益。

## 2. 分工：什么留在 Skill，什么交给大模型

建议将反馈按处理所需权限、证据和动作范围划分。

| 反馈/事件 | 本地处理 | 升级条件 |
|---|---|---|
| 姿态跟踪误差、小幅目标漂移 | 控制器重算 IK/视觉伺服；限制在授权工作区内 | 残差持续越界、标定疑似失效、修正超出边界 |
| 一次 IK/规划失败 | 不执行失败轨迹；尝试登记过的等价姿态或局部重规划 | 没有已检查候选、需要换臂/换目标或超出恢复预算 |
| 已确认空抓、目标身份仍稳定 | 先确认物体已受支撑，再开爪、退回、重定位、重抓 | 持握状态不明、目标改变、恢复后仍空抓 |
| 短暂遮挡/丢跟踪 | 标记 unknown；在已有安全条件下暂停相关动作并做有界重观测 | 无法重获、多个候选无法消歧；不可用遮挡直接判空抓 |
| 已抓物体滑动 | 按对象和硬件允许的登记策略减速/就近支撑；持续感知 | 无可行局部流程、持握证据失效或无法稳定 |
| 目标身份不确定、语言歧义、托盘被替换 | 暂停依赖该事实的动作，提交相关证据 | 由大模型重选目标、修改计划；仍歧义才交给人 |
| 连续没有任务进展、相同恢复反复出现 | 记录失败签名和阶段进展量 | 超出次数或时间预算后请求大模型，禁止无界重试 |
| 驱动器故障、力/速度越限、传感器过期 | 本地立即进入适合当前持物状态的停止/保持流程 | 可同时通知大模型，但不得等待模型决定是否停 |
| 正常阶段完成 | 后置条件满足则由状态机自动推进 | 新阶段需要尚未授权的任务选择或证据不足 |

“抓取未闭合”需要细分：命令未送达、驱动器异常、物体挡住夹爪、真正空抓都可能表现为未到闭合位置。夹爪闭合命令、实际开口、接触证据应分别记录；完全闭合也可能意味着什么都没抓到。

常规阶段切换无需自动触发大模型。可以保留闭合、正式运输、释放等本地检查点，但检查点由可靠判据直接通过时继续执行。实验中的“阶段都调用 Astra”是待比较的调度条件，不应被当作最终架构要求。

## 3. Skill 要成为可执行的闭环单元

以 `pick_and_place(target_id, destination_id, constraints)` 为例：一次委托可覆盖接近、抓取、试抬、运输、放置、释放和验证，但每阶段都有自己的反馈周期。

```text
LOCATE → PREGRASP → ALIGN → CLOSE → TEST_LIFT → TRANSPORT
                                                   ↓
DONE ← VERIFY ← RETREAT ← RELEASE ← LOWER_TO_SUPPORT

局部失败 → RECOVER → 从重新验证后的阶段恢复
证据不足/越过边界/恢复耗尽 → NEEDS_REPLAN
```

一个 Skill 的契约至少包含：

```yaml
name: pick_and_place
version: proposed-v1
inputs: [target_id, destination_id, constraints, observation_version]
preconditions:
  - target_identity_valid
  - destination_valid
  - calibration_valid
  - perception_fresh
invariants:
  - preserve_target_and_selected_arm_unless_reauthorized
  - stay_inside_checked_workspace_and_motion_limits
  - do_not_transport_without_current_grasp_evidence
  - do_not_release_without_support_and_destination_evidence
recovery:
  empty_grasp: reacquire_and_regrasp
  planning_failed: try_checked_alternative
limits:
  local_retries: 1  # 第一版设计值，后续在开发集冻结
  deadline: per_task_config
outputs:
  status: [RUNNING, SUCCEEDED, NEEDS_REPLAN, SAFE_STOP, CANCELLED]
  fields: [phase, verified_facts, evidence_refs, failure_code, next_options]
```

`start/tick/cancel/checkpoint` 应由运行时实现。`tick` 接收新观测并有界返回，不执行直到完成才返回的长阻塞脚本。取消后返回当前物理状态；已执行动作不能撤销。

运动后置条件使用实测到达误差；抓取后置条件使用对象证据；成功后置条件使用任务语义。三者不能相互替代。

## 4. 结构化状态：保存证据，同时保存不确定性

建议将用户提出的摘要扩展为“可计算的事实 + 有界近期记录 + 可检索原始证据”。以下是字段示例，不是实测状态：

```yaml
task: 将指定杯子放进托盘
task_id: episode_example
state_revision: 17
target:
  track_id: cup_03  # 感知创建的身份，不是仿真内部物体 ID
  identity: confirmed
  evidence_refs: [frame_041_head, frame_041_wrist]
destination:
  track_id: tray_01
  placement_region: region_02
phase: transport
verified_completed: [identify_target, grasp, test_lift]
facts:
  holding_target:
    value: supported_by_evidence
    sources: [object_tcp_relative_motion, gripper_measurement]
    observed_at: observation_047
    valid_until: configured_freshness_limit
    invalidated_by: [release, slip, identity_lost, incompatible_new_observation]
failures:
  - phase: grasp
    code: empty_grasp
    attempt: 1
    action_ref: action_032
    evidence_ref: frame_034
    changed_parameter: approach_direction
    recovery_result: verified
remaining: [place, release, verify]
versions:
  calibration: calibration_sha256
  scene: local_scene_revision
  skill: skill_sha256
  perception: perception_config_sha256
```

实现规则：

1. `commanded / observed / inferred / verified` 分开。模型说“抓住了”只成为待验证假设，不能直接写入权威的 `verified_completed`。
2. 由确定性的 reducer 根据动作 ACK、感知回执和验证结果更新状态；大模型提出子目标/解释/计划修改。若要让模型写状态，只允许写候选字段，再由规则验证。
3. “已经试抬成功”是历史事实；“当前仍持握有效”是会过期的事实。出现滑落后保留前者并撤销后者，回退当前阶段。
4. 位姿、相机外参、对象身份都带时间戳、frame、版本和可用性。未校准的置信度不能伪装成统计概率。
5. 标定变化使相关空间事实失效；局部障碍变化只使依赖该区域的路径失效。任务身份等无关事实不必全部清空。
6. 默认向大模型提供当前三视角、最近 2–3 段动作与实测结果、事件前后图像、结构化状态、有关失败动作及几何说明；必要时检索旧证据。原始日志保留在外部。
7. 不把一切压成六条短句。失败过的接近方向、夹爪命令、动作尺度、目标身份变化等关键信息必须可恢复，否则会重复失败。

## 5. 事件触发：检测任务是否进展，而非只看机械臂是否运动

### 事件定义

每个事件包含 `event_id / type / severity / observation_version / evidence_refs / affected_resources / allowed_local_recovery / deadline`。

- 接近阶段：目标相对 TCP 的位姿误差是否持续下降、可行路径是否存在。
- 抓取阶段：夹持状态是否出现可信变化；试抬时对象是否离开支撑面，是否相对 TCP 保持近似稳定。
- 运输阶段：对象到目标区域的距离是否下降，持握和障碍约束是否仍有效。
- 放置阶段：对象是否得到支撑，是否处于目标区域内，释放撤手后是否保持稳定。

允许机械臂在动但任务无进展。反之，合理等待夹爪闭合、物体稳定、力控接触时，不应仅因短时静止就报停滞。

二维共动只能生成候选：腕相机随手运动会产生自运动，固定相机也存在遮挡和投影退化。优先在统一空间坐标中跟踪对象与 TCP 的相对关系；只有 RGB 时，至少使用固定视角、补偿相机运动、多帧特征及夹爪证据，并保留 unknown。

### 调度逻辑

```text
收到新观测 / 动作 ACK：
  先检查本地硬约束、感知时效与版本
  更新事实、阶段和进展指标
  若动作越界：停止相关执行，进入合适的保持/停止状态
  否则若已知失败且有可用局部恢复预算：运行登记恢复
  否则若身份/任务变化、持续无进展、恢复失败：提交一次合并后的模型请求
  否则若关键后置条件满足：本地推进阶段
  否则若授权时限/最大未复核窗口到期：重新验证，必要时请求模型
  否则继续本地闭环
```

同一异常合并、去抖；恢复后仍满足异常条件或严重程度上升时允许再次升级。本地停止和新出现的严重事件不受普通事件限流影响。

第一版保留有界复核窗口，避免监控漏检后永久不调用模型。窗口应对应场景变化和动作风险；实机要同时限制墙钟时间、累计位移和观测年龄，不能仅按控制步数。对有可靠验证器的阶段，可逐步将周期大模型调用替换为本地授权续期。

初始部署宜在相关动作暂停、状态稳定后同步请求大模型。若后续使用异步请求，返回建议必须核对依赖的状态/标定/场景版本和当前前置条件；过期结果重新验证或丢弃。网络重试不能重复执行已 ACK 或执行状态未知的动作，命令需要唯一 ID 与状态查询。

## 6. RoboDojo 的具体落点

### 6.1 复用与缺口

| 现有入口 | 可复用内容 | 新增/修正 |
|---|---|---|
| [framework_io.py](../robot_agent_eval/framework_io.py) `PublicEnv` | 公开 RGB-D、状态、原生 step、IK、动作回执 | 统一 ObservationPacket；区分命令与实际夹爪状态；补时效、frame 和取消语义 |
| [native_server.py](../robot_agent_eval/native_server.py) | 同步渲染；显式开启公开深度和标定 | 传感器同步/版本检查；单独登记扩展观测条件 |
| [modular_pickup.py](../robot_agent_eval/modular_pickup.py) `Executor` | 小步运动、到达检查、闭合、3 cm 试抬、有限恢复 | 拆成可取消的 tick；参数化恢复；增添运输、放置和释放验证 |
| 同文件 `AnchorVerifier` | 锚点跟踪及深度高度变化的验证雏形 | 身份连续性、相机运动补偿、对象/TCP 相对运动、unknown、保存每次 mask；现状不能视为可靠持握检测器 |
| [ablation_perception.py](../robot_agent_eval/ablation_perception.py) | USD 相机反投影、局部几何、link6/TCP 转换 | 统一 GeometryContract；覆盖多相机、动态外参及分辨率变化 |
| [monitor.py](../experiments/supervision-efficiency/implementation/monitor.py) | 5 步 ACK 的颜色候选、阶段/异常事件、去抖 | 参数化目标跟踪；增加阶段进展和验证器；保留原版用于既有对照 |
| [controller.py](../experiments/supervision-efficiency/implementation/controller.py) | VLA 15 步刷新与 Astra 审查分离、有界上下文、事件合并 | 新建 SkillRuntime、权威状态 reducer、本地恢复表及动作执行门 |

当前 Monitor 明确只针对淡紫铲子。它以位置/旋转/夹爪和像素变化检测停滞，机械臂来回微调可能一直不触发；不能原样推广到杯子、托盘或所有任务。

### 6.2 建议新增模块

在新的隔离实验目录实现，保留现有源码、历史实验和排队配置：

```text
experiments/closed-loop-skills/             # 建议新增，尚未实现
  geometry_contract.py                    # 相机、TCP、单位、时间和版本
  observation_adapter.py                  # RoboDojo 公开传感器适配
  task_state.py                           # 事实 reducer、失效与证据索引
  validators.py                           # 到达、持握、支撑、任务完成
  skill_runtime.py                        # tick/cancel/阶段执行门
  recovery_registry.py                    # 已知故障 → 有界恢复
  event_scheduler.py                      # 去抖、升级、授权窗口
  skills/pick_and_place.py
  configs/ manifests/ runs/ results/
```

先在 `general_pickup` 验证抓取与恢复，原生上限仍为 200 步。已有监督对照继续使用相同 VLA：H50 预测只执行前 15 步，每 5 步 ACK；延长 Astra 审查至 45 步不代表连续执行旧预测 45 步，修正后必须刷新预测。

关键动作执行门应检查待执行段：若即将释放但支撑/目的地证据不成立，截在释放动作之前。不能先执行 5 步后才宣称做了“释放前检查”。接触区更密集观测属于新的执行配置，需要单列实验，不能静默混入原调度对照。

已有 `general_pickup` 只要求抬升 10 cm，不验证运输放置。随后可用 `pack_objects_into_box` 等原生任务验证较长流程，但要保留原生对象、指令、附加归位要求和步数限制。用户的“指定杯子放进托盘”若无对应原生案例，创建单独扩展任务和独立标签，不把自定义成功算成原生任务成功。

运行时只读取公开 RGB/RGB-D、标定及机器人本体状态；对象真值、实例 ID 和奖励内部条件仅供独立离线评估器使用。碰撞、接触等新增传感器若超出现有观测许可，也须成为明确的新实验条件。

### 6.3 先把几何变成可靠接口

当前本机代码约定：

- 像素是 `[row, col]`；深度是沿光轴的米制 `distance_to_image_plane`，不是沿射线的欧氏距离。
- 原生外参在当前适配路径解释为 USD camera-to-world，+Y 向上、−Z 朝前。必须再明确这里的 world 与动作所用 environment origin 的关系；多环境场景尤其不能遗漏环境原点变换。
- 转为 OpenCV 光学系（+X 向右、+Y 向下、+Z 向前）时，`T^E_Ccv = T^E_Cusd · diag(1,-1,-1,1)`，再计算 `p^E = T^E_Ccv · [ z K⁻¹ [u,v,1]ᵀ ; 1 ]`。畸变图像先校正。
- 实际 EEF 控制 frame 为 `link6`。代码声明的接触中心位置为 `p_TCP = p_link6 + R_link6 [0.145,0,0]ᵀ`，完整朝向转换也要应用，不能仅平移。
- 若上层指定 TCP 目标，执行层计算 `T^E_link6_goal = T^E_TCP_goal · (T^link6_TCP)⁻¹`，然后调用现有 IK/控制器。这个 145 mm 是当前模型中的声明，需核对资产和执行接口，不能作为所有实机的已测常数。
- `Contact-GraspNet` 候选使用 Panda 抓手基座约定，已有 [graspnet_calibration.py](../robot_agent_eval/graspnet_calibration.py) 使用 103.4 mm pad 偏移后转换到 ARX。候选原点不能直接当作 ARX 指尖。

0.145 m 的工具长度下，10° 朝向误差可造成约 25 mm 的接触中心偏差。因此 link6 的毫米级位置到达不保证指间准确对齐。

固定相机的安装变换可版本化保存；腕相机必须随采集时刻更新：`T^E_camera(t) = T^E_link(t) · T^link_camera`。不能把初始腕相机外参当作常量。头相机配置的初值可在 [camera_config.yml](/path/to/RoboDojo/env_cfg/camera/camera_config.yml) 找到，但运行时矩阵才是当前观测依据。

给大模型的几何信息包括简短的轴向、控制点、夹爪闭合方向、实际 TCP、版本以及叠加在图像上的坐标轴/抓取点。矩阵运算由工具执行；不能只写长提示让模型每轮手算。

验证不能止于投影反投影往返相等。还要用多个已知位置的标定点、不同腕姿态和三轴小位移验证：空间移动方向、重投影、TCP 到达、夹爪开口与接触几何。往返检验只说明同一套公式代数自洽。

## 7. 实机实现：保持契约，替换传感器和执行适配

目前未确定实机型号、相机、夹爪及 SDK；以下按固定基座机械臂、平行夹爪、固定/腕 RGB-D 相机给出实施路径。是否有实际开口、力矩或触觉回读应以硬件能力为准，缺失项显式 unknown。

### 7.1 标定与接口

1. 标定相机内参/畸变、RGB 与深度对齐、深度尺度；验证不同距离和视野位置的误差。透明/反光杯子的无效深度不能以补全结果假装实测。
2. 固定相机标定 robot-base-to-camera；腕相机做手眼标定，覆盖多姿态并留出未参与拟合的姿态验证。腕图像使用采集时刻的关节插值/FK，而非请求处理时刻的姿态。
3. 标定 flange/link-to-TCP、指垫位置与闭合轴、实际开口曲线、软指垫受力后的变化；更换夹具或相机后提升版本并使依赖事实失效。
4. 核对驱动器命令是法兰、工具 TCP、绝对位姿还是增量，速度/加速度和四元数约定是什么。若厂商已配置 TCP，不再重复加工具偏移。
5. 用独立标定物/治具验证落点、腕相机运动、夹爪开口和小范围抓放；验收容差依据物体尺寸与环境间隙确定。

### 7.2 控制与停止

使用硬件 SDK，或硬件支持时通过 ROS 2 的 action、tf2、运动规划与伺服接口接入相同 SkillRuntime。底层控制保持厂商所需实时频率；任务状态机与视觉更新按传感器能力运行。大模型在事件发生时调用，不进入关节控制周期。

等待大模型期间世界继续变化：持握对象时保持适合物体的夹持/姿态控制，必要时走已验证的就近支撑流程；独立监控继续运行。异常返回后的动作必须基于新观测重新检查，禁止照着十几秒前的图像直接执行。场景无法保持可控时，本地停止并上报。

“停止”不等于断电或开夹爪。抓着杯子时贸然开爪会制造新故障。停止、减速、保持和安全支撑分别由对象/硬件特性决定，不能用统一的“失败就开爪”恢复。

### 7.3 杯子放托盘的具体闭环

| 阶段 | 反馈与动作 | 必须满足的推进条件 |
|---|---|---|
| 识别/定位 | 大模型指定杯子与托盘身份；分割/跟踪提供位置与可抓区域 | 身份、几何和可达性有效；杯把/杯身抓取策略明确 |
| 接近/对齐 | 局部规划到预抓点；视觉伺服细调；近接触减速 | 实测 TCP 到位，指垫与对象局部几何相容 |
| 闭合/试抬 | 回读开口/电流/触觉（若可用），小幅试抬，多帧观察 | 对象离开支撑、对象相对 TCP 稳定；单次共动不够 |
| 运输 | 规划携物路径，持续检查持握、对象姿态、障碍 | 对象与目标区域接近；杯子直立等任务约束持续成立 |
| 下放 | 根据杯子完整尺寸和托盘区域计算姿态；低速下降 | 杯底获得支撑、杯身位于有效区域内，必要时用力/视觉联合判断 |
| 释放/撤手 | 支撑成立后渐开夹爪，撤离，再观察 | 杯子留在托盘、与夹爪分离并持续稳定；任务完成 |

运输和放置要维护抓取后的 `T^TCP_object`：由目标对象姿态求 `T^E_TCP_goal = T^E_object_goal · (T^TCP_object)⁻¹`。否则只把 TCP 放到托盘中心，杯底高度、杯身碰撞和杯把方向仍可能错误。相对变换在滑移时失效并重新估计。

## 8. 推荐实施顺序与验证

### 分阶段交付

1. **几何与观测契约**：统一相机/机器人/TCP frame、时钟和单位，完成独立几何验收。交付 GeometryContract、标定版本及误差记录。
2. **事实状态与验证器**：将模型摘要和权威事实分离；修复身份漂移/unknown；增加阶段进展。先离线验证，再做影子监控。
3. **闭环抓取 Skill**：把现有 Executor 拆成 tick 状态机，注册一次有界恢复，输出明确故障与证据。先完成抓取，不同时扩展全部任务。
4. **事件调度**：接入执行门、去抖、恢复升级及有界授权。保持 VLA 节拍、模型、观测条件和预算一致，与周期审查比较。
5. **运输放置与实机适配**：补完整 pick-and-place 后置条件，再用同一状态机替换硬件适配层。对实机持续变化和网络延迟另行验证。

### 实验应分别回答的问题

| 对照 | 固定什么 | 验证什么 |
|---|---|---|
| 周期审查 vs 事件审查 | 相同监控器/状态/技能、VLA 刷新、预算 | 调度是否减少等待且不明显损失成功 |
| 本地恢复关 vs 开 | 相同事件/故障、初始场景与动作能力 | 已知故障是否能少调用模型并恢复 |
| 完整历史 vs 状态+近期记录+证据检索 | 两组都有相同权威状态、相同调度和技能 | 历史压缩的资源收益与遗忘代价 |
| 几何提示 vs 几何工具/执行检查 | 都给出正确坐标语义，保持观测许可 | 可靠转换和约束落实是否减少调整与误动作 |

先用开发帧和受控序列检验空抓、遮挡、错目标、滑落、一直微调却不接近目标、托盘移动、标定过期、响应过期。记录事件漏检/误触发、发现延迟、错误阶段推进、恢复成功和监控开销。仿真物体真值只进入离线标签；实机可用独立录像、治具或独立测量建立评价依据。

在未见布局中随机化组别顺序并配对重复；按布局/任务聚合统计，不能把同一布局三次重复当作三个独立场景。若要宣称成功率非劣，事先定义容忍差值与所需样本，单布局试跑不能支持这一结论。

报告预算内成功、原生成功/失败/未知、墙钟时间、模型阻塞、VLA/感知/监控/记录成本、控制步数、恢复次数、API 提交与完成、输入/缓存/输出。失败前的短耗时不能当作提速；可同时报告按固定预算惩罚的完成时间和成功曲线。费用汇总包含失败尝试，缓存与缺失 usage 按实际口径保留。

对现有 queued 第二部分，先保留其冻结身份；增强验证器、RGB-D 或本地恢复后形成新的独立批次。本方案给出实现路线，不把排队文件、已有实现或单次恢复录像当成新方法效果。
